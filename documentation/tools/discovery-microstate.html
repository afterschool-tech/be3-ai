Discovery & microstate tools

Search verification and recovery; onboarding and collection summaries; microstate-driven disambiguation, confirmation, and collection.

What it does

  • Shadows product.search results from accumulatedResults; verifies that results match the user’s search_intent.
  • If no results or AI says “NO” (irrelevant), enters recovery: infers a related category from store inventory, fetches a small product set from that category, updates search_context and reference_map, returns a “couldn’t find exactly X, but here are options from [category]” message.
  • Stores last_suggestion for follow-up; builds product_attributes_map for clause resolution.

When to use

  • Typically invoked in the same turn as product.search (orchestrator/pipe); not called in isolation by the user.

What it does

  • Triggered when search is vague or broad. Resolves category from query or category (fuzzy match).
  • If no category: returns onboarding — welcome message and top categories as buttons (and optional list). Can reflect price_min/price_max in copy.
  • If category resolved: fetches a sample of products, builds stats (brands, min price, etc.), returns a rich collection summary and sub-category pivots with WhatsApp buttons/lists.

Params

  • query, category (slug or ID).

All microstate tools return directResponse: true so the response layer sends their message directly to the user without AI generation — preserving deterministic prompts and avoiding personality drift.

microstate.disambiguate

  • Presents options (e.g. categories, products) with an optional numbered list and up to 3 WhatsApp buttons; supports baseIndex for pagination, controls: { more, cancel, skip, recommendedIndex }.
  • Params: reason, message, options (array of { label, value } or strings), baseIndex, controls, parentIntent, missingParam.
  • Emits buttons like __nav:more__, __flow:cancel__, __flow:skip__ when controls are set.

microstate.confirm

  • Asks a yes/no question; optional context object is rendered above the question. Returns expects: 'yes_no'; WhatsApp can show Yes/No buttons (ms_yes, ms_no).

microstate.collect

  • Asks for a specific parameter value (e.g. order number, quantity); paramName, message, optional hint, parentIntent.

microstate.buttons

  • Sends a message with up to 3 custom buttons ([{ id, title }]). Used for generic microstate prompts (e.g. “View cart” / “Continue shopping”).
