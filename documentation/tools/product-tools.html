Product tools (product.*)

Search, details, comparison and facet helpers that power almost every shopping journey.

What it does

  • Runs the main product search against the backend (structured + optional semantic/vector search).
  • Respects category, price range, vendor tag and dynamic attribute filters from the intent resolver.
  • Persists search snapshots and search_context so later turns (add to cart, compare, filters) can reuse the same result set.
  • Builds a product_attributes_map for up to 10 products so clause-based filters like “the white ones” can map to real attributes.

Key params (from toolMapper)

  • query — user search phrase or normalized product_name.
  • category — category id/slug, usually resolved from the pipeline.
  • price_min, price_max — numeric price filters.
  • tag — vendor tag when scoped by vendor.
  • attributes — dynamic filters (e.g. { color: "white", b: "Apple" }).
  • limit, page, sort — paging and ordering options.

State & engineered tokens

  • Writes search_context with product_ids, product_attributes_map, category, vendor and clauses.
  • Updates reference_map and user_query_map for pronoun/ordinal resolution (e.g. “add the first one”).
  • Emits:
    • __nav:more:<snapshotId>__ — next page.
    • __filter:clause:<snapshotId>:<attrCode>:<clauseName>__ — apply a semantic clause.
    • __filter:value:<snapshotId>:<attrCode>:<value>__ — apply an exact facet value.

What it does

  • Fetches the full product payload from the backend for a single product_id.
  • Normalizes it into a lean, storefront-friendly shape via processProductData.
  • Backfills missing attributes/specs from recent search snapshots or a secondary search if needed.
  • Marks the product as currently_viewing in user state for follow-up coreference.

Integration

  • Used directly by the product.getDetails tool call, and internally by product.compare.
  • Downstream intents like “compare these two” and “add it to cart” rely on the IDs this tool surfaces.

Engineered buttons

  • __cart:add:<productId>__ — add this product to cart.
  • __product:compare:<productId>__ — open a compare microstate with this as the first product.
  • __vendor:info:<vendorKey>__ — jump to vendor.getInfo for the vendor behind this product.

What it does

  • Resolves 2–4 products (by ids or structured product_segments) and returns a normalized comparison array.
  • Expands attributes (codes + human labels) so the LLM can reliably talk about shared fields.
  • Updates reference_map and last_search so subsequent pronouns (“the samsung one”) resolve inside the comparison set.

When to use

  • Intents like product_compare when the user explicitly asks to compare items.
  • Microstate compare flows kicked off by __product:compare:<id>__ buttons from product.getDetails.
  • product.getAdvice — deterministic advice helper for a category/need; typically wrapped by higher‑level AI personalities.
  • product.findCheapest — thin wrapper over product.search with sort = price_asc; used for “cheapest X” flows.
  • product.checkAvailability — resolves a product then returns a simple availability snapshot.
  • product.similarItems — finds similar products within the same category as a target item.
  • product.getImage — runs a search but strips results down to id/name/price so the client can render an image gallery.
  • product.facets — discovers facet values for a specific attribute (e.g. storage, color) and emits __facet:select:…__ buttons that map back into product.search without re‑entering NLU.
